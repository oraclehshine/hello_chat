# Hello Chat 高并发改造更新

日期：2026-06-09

## 本次已完成变更

### 1. Spring Cloud Alibaba 高并发基础骨架

- 后端 `pom.xml` 已接入 `Spring Cloud` 与 `Spring Cloud Alibaba` 相关依赖管理
- 接入了 `Nacos Config`、`Nacos Discovery`、`Sentinel`
- 应用启动类已增加服务发现入口
- `application.yml` 已补充：
  - `Nacos` 配置中心与注册中心开关
  - `Sentinel` 控制台入口
  - 并发节点参数
  - Kafka 序列化与消费配置

相关代码：

- `backend/pom.xml`
- `backend/src/main/java/com/hellochat/backend/HelloChatApplication.java`
- `backend/src/main/resources/application.yml`

### 2. WebSocket 会话模型升级

- 原来的 `userId -> WebSocketSession` 单连接模型已改成多连接模型
- 新增 `UserSessionRegistry` 抽象
- 新增 `RedisBackedUserSessionRegistry`，把在线路由登记到 Redis
- `ChatWebSocketHandler` 已改成通过注册中心管理会话

当前效果：

- 支持同一用户在本机多个连接并存
- 为多节点路由预留 Redis 基础
- 连接建立和释放时同步维护在线状态缓存

相关代码：

- `backend/src/main/java/com/hellochat/backend/websocket/UserSessionRegistry.java`
- `backend/src/main/java/com/hellochat/backend/websocket/RedisBackedUserSessionRegistry.java`
- `backend/src/main/java/com/hellochat/backend/websocket/ChatWebSocketHandler.java`

### 3. 运营写入从热路径剥离

- 新增异步线程池配置
- 新增 `AdminDashboardAsyncService`
- 聊天、群聊、朋友圈、上传、在线状态等链路中的后台记录改为异步处理

当前效果：

- 发消息、发动态、上传文件不再同步阻塞后台统计写入
- 主业务响应路径更短

相关代码：

- `backend/src/main/java/com/hellochat/backend/config/AsyncConfig.java`

## 当前架构状态

当前后端已经从“单体同步直推模型”演进到下面的形态：

- 接入层有 Sentinel 限流
- 热点状态进入 Redis
- 聊天写入与推送通过 Kafka 解耦
- WebSocket 路由通过 Redis 管理
- 运营与观测侧写入异步化

这意味着系统已经具备高并发演进的基础骨架，但还没有完成所有链路的统一治理。

## 下一阶段开发计划

### 第一优先级

- 把群聊链路也接入 Kafka 事件流
- 群消息写库后通过 Kafka 异步广播，而不是同步触发推送
- 把群未读数与群会话摘要接入 Redis

### 第二优先级

- 把单聊和群聊的推送事件统一成更稳定的事件协议
- 增加消息重试、失败补偿和死信处理
- 增加消息幂等键，防止重复投递

### 第三优先级

- 把搜索、推荐、热门话题等读多写少模块进一步缓存化
- 引入更细粒度的用户级、群级限流规则
- 增加 Kafka 消费监控与积压监控

### 第四优先级

- 拆分 `auth / chat / group / ws-gateway` 多模块或多服务骨架
- 逐步从单体内高并发改造过渡到服务级拆分

## 目前仍需注意的问题

- 群聊推送链路还没有完成 Kafka 化
- 群未读与群摘要还没有接入 Redis
- 部分历史接口仍存在安全收紧空间
- 目前做的是高并发骨架与热路径改造，不是最终形态
